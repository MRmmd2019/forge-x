## معرفی کلی و فلسفه طراحی

توسعه‌دهندگان وب اغلب پروژه‌های چند فایلی، سایت‌های استاتیک، یا وب‌سرویس‌های کاملی می‌سازند که برای میزبانی در لبه شبکه (Edge Network) کلودفلر مناسب هستند. با این حال، پلتفرم **Cloudflare Workers** متکی بر معماری ایزوله جاوااسکریپت V8 بوده و به صورت پیش‌فرض انتظار یک **ماژول استاندارد ES واحد (`export default { fetch }`)** را بدون وابستگی‌های مستقیم فایل‌سیستم سرور دارد.

**AutoForge** یک کامپایلر، پکر و محیط کار پیشرفته و مستقل است که هر پروژه وبی (شامل سورس‌کدهای TypeScript/JavaScript، صفحات HTML/CSS، تصاویر، فونت‌ها و روت‌های API) را به صورت **خودکار و بدون نیاز به پیکربندی (Zero-Config)** دریافت کرده، تحلیل و تعمیر می‌کند و در قالب **یک فایل مستقل و بدون نقص به نام `worker.js`** تحویل می‌دهد.

## ویژگی‌های کلیدی و برجسته

* 🚀 **کاملاً بدون نیاز به پیکربندی (Zero-Config):** تشخیص خودکار ساختار پروژه، معماری فرانت‌اند یا بک‌اند، نقطه ورود (`entry point`) و فایل‌های دارایی استاتیک بدون نیاز به نوشتن `wrangler.toml` یا کانفیگ وب‌پک.
* 🛠️ **موتور خودترمیمی جبری (Deterministic Self-Healing):** اگر کد پروژه دارای خطاهای ارجاعی، مسیرهای ایمپورت اشتباه، ماژول‌های ناقص یا ناسازگاری پلتفرم باشد، سیستم به صورت خودکار خطا را عارضه‌یابی کرده و سورس‌کد را در حافظه اصلاح می‌کند (تا ۵ تلاش خودکار).
* 🔒 **امنیت در سطح عمیق فضای کاری:** مقاومت ۱۰۰٪ در برابر حملات Zip-Slip، بمب‌های زیپ (Decompression Bomb)، و پیمایش غیرمجاز مسیرها (Path Traversal).
* 📦 **امبدینگ بدون افت کیفیت دارایی‌ها (Asset Embedding):** بسته‌بندی فایل‌های وب (عکس، فونت، استایل و اسکریپت) به همراه الگوریتم هوشمند هش SHA-256، پشتیبانی از ETag، پاسخ‌دهی ۳۰۴ Not Modified و مسیریابی خودکار برنامه‌های تک‌صفحه‌ای (SPA Fallback).
* ⚡ **استفاده از esbuild با حداکثر سرعت:** کامپایل کدهای مدرن ES2022 در کمتر از چند صدم ثانیه درون رم بدون آلوده کردن فایل‌های دیسک.
* 🌐 **تاییدیه رسمی با Wrangler و شبیه‌ساز ایزوله:** اجرای مرحله ارزیابی واقعی `wrangler deploy --dry-run` در یک محیط مجزا به همراه اسموک تست روت‌های وب برای تضمین کارکرد ۱۰۰٪ ورکر در کلودفلر.
* 📡 **رابط کاربری مدرن با استریم رویدادها (SSE):** نمایش لحظه‌به‌لحظه فرآیند بیلد، لاگ‌های سیستمی زنده، بازرسی کد خروجی و پیش‌نمایش در مرورگر با انیمیشن‌های پویا.

## موتور خودترمیمی هوشمند (Self-Healing Engine)

یکی از وجوه تمایز اساسی AutoForge با باندلرهای سنتی، سیستم خودترمیمی چندلایه‌ای آن است. اگر در مرحله کامپایل esbuild خطایی رخ دهد، سیستم متوقف نمی‌شود؛ بلکه موتور `DeterministicRepairEngine` وارد عمل می‌شود:

```
                  ┌───────────────────────────────┐
                  │      esbuild Compilation      │
                  └───────────────┬───────────────┘
                                  │
                       [خطای کامپایل شناسایی شد]
                                  │
                                  ▼
                  ┌───────────────────────────────┐
                  │    Error Normalizer & AST     │
                  │   تحلیل پیام خطا و یافتن علت  │
                  └───────────────┬───────────────┘
                                  │
                                  ▼
                  ┌───────────────────────────────┐
                  │  Deterministic Repair Engine  │
                  ├───────────────────────────────┤
                  │ • جستجوی فایل در ساختار پروژه │
                  │ • اصلاح مسیرهای اشتباه ایمپورت│
                  │ • تزریق فلگ nodejs_compat    │
                  │ • اکسترنال کردن پکیج‌های خاص  │
                  └───────────────┬───────────────┘
                                  │
                                  ▼
                  ┌───────────────────────────────┐
                  │   تلاش مجدد (Attempts 2..5)   │
                  │   با کد اصلاح‌شده و موفقیت    │
                  └───────────────────────────────┘
```

### سناریوی واقعی:
اگر در یک سورس‌کد نوشته شده باشد:
```typescript
import { Router } from "./router.ts";
import { jsonResponse } from "./response.ts";
```
و فایل‌های موردنظر در حقیقت داخل زیرپوشه `src/worker/core/` باشند، ابزار در **تلاش ۱** خطا را کشف کرده، محل واقعی فایل‌ها را روی درخت پروژه ردیابی نموده و فایل را به شکل زیر بازنویسی می‌کند:
```typescript
import { Router } from "./core/router";
import { jsonResponse } from "./core/response";
```
و سپس در **تلاش ۲** بیلد را با موفقیت و تاییدیه Wrangler به پایان می‌رساند.

## فیلتر هوشمند فایل‌ها و تمیزکاری اسناد (Asset Sanitization)

هنگامی که یک ریپازیتوری گیت‌هاب فشرده‌شده بارگذاری می‌شود، حجم زیادی از فایل‌ها زائد هستند. AutoForge این فایل‌ها را در لایه‌های مختلف فیلتر می‌کند:

| دسته فایل‌ها | نمونه‌ها | شیوه برخورد سیستم |
| :--- | :--- | :--- |
| **متادیتای گیت‌هاب و اکشن‌ها** | `.github/`, `.git/`, `.gitlab/` | فیلتر کامل در مبدا و جلوگیری از استخراج روی دیسک |
| **تنظیمات ادیتورها و کش** | `.vscode/`, `.idea/`, `node_modules/`, `.cache/` | حذف کامل از درخت پروژه |
| **فایل‌های قفل پکیج‌منیجر** | `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` | عدم امبد در خروجی ورکر برای جلوگیری از تورم حجم |
| **مستندات و فایل‌های متنی** | `README.md`, `LICENSE`, `CHANGELOG.md` | نگهداری در پروژه اما حذف خودکار از جدول روت‌های وب |
| **سورس‌های خام تایپ‌اسکریپت** | `*.ts`, `*.tsx`, `*.mts` | پس از کامپایل توسط esbuild، فایل خام از دارایی‌های دانلودی حذف می‌شود |
| **فایل‌های وب و دارایی‌های واقعی** | `index.html`, `style.css`, `.png`, `.svg`, `.woff2` | کدگذاری تمیز با Base64/UTF-8، ثبت در جدول روت‌ها همراه با ETag |

## سازگاری کامل با اکوسیستم Node.js در کلودفلر

پلتفرم Cloudflare Workers از ماژول‌های نود به کمک فلگ `nodejs_compat` پشتیبانی می‌کند. AutoForge این قابلیت را به صورت هوشمند مدیریت می‌کند:

### پشتیبانی بومی:
* ماژول‌های `node:crypto`، `node:buffer`، `node:events`، `node:util`، `node:path`، `node:stream` و `node:async_hooks` به عنوان ماژول خارجی (External) علامت‌گذاری شده و با حداکثر سرعت بومی V8 در کلودفلر اجرا می‌شوند.

### رفع باگ `createRequire(undefined)` در Cloudflare:
در برخی پکیج‌های CommonJS، فراخوانی `createRequire(import.meta.url)` در ران‌تایم کلودفلر به علت `undefined` بودن `import.meta.url` با خطای شدید مواجه می‌شد:
```text
Uncaught TypeError: The argument 'path' must be a file URL object... Received 'undefined'
```
AutoForge یک بنر محافظتی اختصاصی در ابتدای کدهای کامپایل‌شده تزریق می‌کند:
```javascript
import { createRequire as __createRequire__ } from 'node:module';
var require;
try {
  var __cf_meta_url__ = (typeof import.meta !== 'undefined' && import.meta && typeof import.meta.url === 'string' && import.meta.url) || 'file:///worker.js';
  require = __createRequire__(__cf_meta_url__);
} catch {
  require = function(mod) { 
    throw new Error('Dynamic require of "' + mod + '" is not supported in this runtime isolate.'); 
  };
}
```
این اصلاح تضمین می‌کند که کدهای شما بدون هیچ خطایی روی لبه شبکه اجرا شوند.

## معماری پایپ‌لاین ۱۱ مرحله‌ای

فرآیند بیلد از ۱۱ مرحله دقیق و هماهنگ تشکیل شده است:

```
[1. ایجاد فضای کاری ایزوله] ──► [2. اسکن و استخراج درخت فایل‌ها] ──► [3. تحلیل ایستای کد و شناسایی ماژول‌ها]
                                                                                │
[6. کامپایل با esbuild] ◄── [5. اعتبارسنجی طرح بیلد] ◄── [4. طرح‌ریزی جبری یا هوش مصنوعی]
         │
  [خطا رخ داد؟] ──► بله ──► [7. حلقه تعمیر خودکار سورس و طرح] ──► (تلاش مجدد در مرحله ۶)
         │
         ▼ خیر
[8. فیلتر و امبد دارایی‌های وب] ──► [9. تولید کد نهایی ورکر] ──► [10. بازرسی حجم و امنیت باندل]
                                                                                │
                                                                                ▼
                                        [11. ارزیابی رسمی با Wrangler Dry-run و تست ران‌تایم]
                                                                                │
                                                                                ▼
                                                                [موفقیت کامل: worker.js]
```

1. **Workspace Intake:** باز کردن فایل فشرده با تدابیر شدید امنیتی.
2. **Scanner:** دسته‌بندی فایل‌ها به سورس، استاتیک، داکیومنت و کانفیگ.
3. **Static Analysis:** یافتن توابع `fetch`، پورت‌های ورودی و نیازمندی‌های Node.js.
4. **Planning Engine:** انتخاب بهترین حالت ورکر (`worker_native`, `static_with_assets`, `hybrid_api_and_assets`).
5. **Plan Validation:** بررسی تطابق فایل‌های ورودی و مقصدهای کامپایل.
6. **esbuild Compilation:** باندل کردن سریع کد جاوااسکریپت با فرمت استاندارد ESM.
7. **Deterministic Repair Loop:** تشخیص و رفع خودکار خطاهای پیش‌بینی نشده تا ۵ بار.
8. **Asset Embedding:** فیلتر فایل‌های زائد و تبدیل دارایی‌ها به جدول روت‌های مجازی.
9. **Worker Generation:** تجمیع کدهای کامپایل‌شده با روتر اختصاصی، مدیریت ETag و کش.
10. **Bundle Inspector:** ارزیابی سلامت فایل تولیدشده و بررسی سقف ۶۴ مگابایتی کلودفلر.
11. **Wrangler Dry-Run & Runtime Smoke Test:** آزمایش نهایی بیلد در محیط رسمی کلودفلر.

## راهنمای استفاده از رابط کاربری وب

1. **آپلود پروژه:** فایل فشرده (`.zip`) پروژه خود را در کادر اصلی بکشید و رها کنید (یا به کمک کلید انتخاب فایل آپلود کنید). همچنین امکان انتخاب پوشه کامل به صورت مستقیم وجود دارد.
2. **پیکربندی اختیاری:**
   * **Minify Code:** فشرده‌سازی حداکثری فایل خروجی جاوااسکریپت.
   * **Target:** انتخاب استاندارد خروجی (پیش‌فرض: `es2022`).
   * **AI-Assisted Planning:** فعال‌سازی هوش مصنوعی Gemini برای پروژه‌های پیچیده و مبهم.
3. **شروع بیلد:** کلید **"Start Autonomous Build"** را فشار دهید.
4. **رهگیری زنده:** مراحل ۱۱‌گانه به صورت زنده با لاگ‌های تفکیک‌شده و رویدادهای سرور (SSE) نمایش داده می‌شوند.
5. **دریافت خروجی:** پس از اتمام موفقیت‌آمیز، می‌توانید فایل `worker.js` را دانلود کرده یا مستقیماً در مرورگر پیش‌نمایش آن را مشاهده کنید.

## نحوه استقرار (Deploy) در Cloudflare Workers

پس از این‌که فایل `worker.js` تولید شد، به سادگی می‌توانید آن را در کلودفلر مستقر نمایید:

### روش ۱: از طریق داشبورد کلودفلر (آسان‌ترین روش)
1. وارد پنل کاربری خود در [dash.cloudflare.com](https://dash.cloudflare.com/) شوید.
2. از منوی سمت چپ به بخش **Workers & Pages** بروید.
3. روی گزینه **Create Application** و سپس **Create Worker** کلیک کنید.
4. پس از نام‌گذاری، روی **Deploy** کلیک کنید و سپس وارد بخش **Edit Code** شوید.
5. تمام محتوای فایل `worker.js` دانلودشده را درون ادیتور کپی کرده و دکمه **Save and Deploy** را بزنید.

### روش ۲: از طریق خط فرمان Wrangler CLI
```bash
# ایجاد یک پوشه تمیز
mkdir my-deployment && cd my-deployment

# انتقال فایل خروجی به این پوشه
cp /path/to/downloaded/worker.js ./index.js

# ایجاد فایل پیکربندی wrangler.jsonc
cat << 'EOF' > wrangler.jsonc
{
  "name": "my-worker",
  "main": "index.js",
  "compatibility_date": "2024-09-23",
  "compatibility_flags": ["nodejs_compat"]
}
EOF

# انتشار در کلودفلر
npx wrangler deploy
```

## راهنمای خطاهای متداول

### خطای Error 1003 (Direct IP access not allowed)
* **علت:** ارسال مستقیم درخواست با آی‌پی کلودفلر به جای استفاده از نام دامنه ورکر.
* **راه‌حل:** در مرورگر آدرس کامل دامنه را وارد کنید (مانند `https://my-worker.workers.dev`). در برنامه‌های کلاینت مانند V2Ray، فیلدهای **Host** و **SNI** را حتماً با نام دامنه ورکر مقداردهی کنید.

### خطای Uncaught TypeError: The argument 'path' must be a file URL object
* **علت:** ناسازگاری `createRequire(import.meta.url)` در کلودفلر.
* **راه‌حل:** در آخرین نسخه AutoForge این مورد کاملاً خودکار اصلاح شده است و نیاز به هیچ تغییری از سمت کاربر نیست.
